# morsec threat model (STRIDE)

**Scope:** morsec as on `main` at commit `2370043` (waves 1–3: L01–L17 and L30 merged), macOS,
CLI only. Written by the `hardening` loop, the pre-release part of L24 (`docs/PLAN.md`); L24
extends it. Requirement ids are the ARI-42 ids used in `ARI42.md`.

morsec keeps secrets in the login keychain and lets coding agents use them without seeing them:
swap mode (an HTTPS proxy that puts the value into requests to bound hosts), run mode (msd runs
the command), and `ms mcp` (typed tools over run mode). On macOS the agent and `msd` run as the
same Unix user. Most of the design exists because of that.

Out of scope here: mint mode (L18–L20, not built), Linux (L21), the menu-bar app (L25, deferred),
the release pipeline itself (L10/L28; see GW-2 in `ARI42.md`).

## Assets

| Asset | Where it lives | Who can read it | Who can write it |
|---|---|---|---|
| Vault values (API keys, DB passwords, SSH keys, git tokens) | Login keychain items, service owned by morsec (`crates/ms-vault/src/macos/mod.rs`) | `msd` only, through `KeychainVault::with_secret`; briefly in msd memory in zeroizing buffers; in the upstream request (swap) or the child process (run) | `msd`, on `PutKey` from `ms add` / `ms import` (value sent as a raw IPC frame) |
| Keychain items and their ACL | Login keychain, pinned by path from the user database (not `$HOME`) | ACL allows only the signed `msd` (designated requirement `cc.morsec.msd`); items sealed against overwrite | `msd`. Any same-user process can delete the keychain file or make items unusable (DoS), and the user can click "Always Allow" on a dialog another binary raises |
| Internal keys (`morsec/rules-hmac`, `morsec/receipts-hmac`, seal key) | Keychain, reserved `morsec/` names | `msd` only; never resolvable as `ms://morsec/...` | `msd` at `ms init` (`reset_internal_keys`) |
| CA private key | Keychain, non-extractable P-256 (`CaKey`), item `morsec/ca` | Nobody: no private-key bytes exist outside the keychain; `msd` can ask it to sign (`sign_sha256`) | `msd` at `ms init` (`reset_ca_key`) |
| CA certificate and leaf certificates | `morsec/ca-cert` in the vault (authoritative); `ca.pem` and connector bundles (`~/.morsec/*.pem`) are exports only; leaves are in msd memory | Everyone (public) | `msd`. The CA carries X.509 name constraints for the bound hosts only |
| Approvals: the pending request | msd memory (`ms_approve::HumanApprover`), one at a time | `ms approve` outside an agent session | Created by msd from the real request; decided by a person, then Touch ID raised by msd |
| Approval tokens | msd memory; HMAC-SHA256 over (id, scope, session, key, argv hash, cwd, expiry) with an in-memory key | `msd` | `msd`; `ms stop` revokes all (`revoke_all` rotates the key) |
| Receipts | `~/Library/Application Support/morsec/receipts/` (JSONL, hash-chained, each record HMAC'd with `morsec/receipts-hmac`) | The user (`ms log`); chain check by anyone, HMAC check by msd only | `msd` appends. A same-user process can delete or truncate files (detected: rewrite; not detected: tail truncation) |
| Rules store | `~/Library/Application Support/morsec/rules.toml` + `.mac` (MAC with `morsec/rules-hmac`); per-project `.morsec.toml` (tighten only) | Everyone who is the user | `msd` (`RulesStore::save`); loosening needs an approval. The file is agent-writable but a bad MAC fails closed |
| Kill-switch state and rules rollback floor | Keychain item `morsec/daemon-state` (`running|stopped v=<floor>`) and msd memory | `msd` | `ms stop` (no approval), `ms start` (approval) |
| Connector settings | `~/.claude/settings.json`, `~/.claude.json`, `$CODEX_HOME/config.toml`, `~/.morsec/connect/*.json` | The user and the agent | `ms connect` / `ms disconnect`; also the agent (same user) |

## Actors

| Actor | What it can do | What it should never get |
|---|---|---|
| **The agent** (Claude Code, Codex and their child processes; same Unix user; may be prompt-injected or simply misbehave) | Run any program as the user; read and write every file the user can; open the socket; use the proxy; call `ms`, `ms mcp`, `ms run`; detach a process from its session; rename a binary to `claude`; write to the user's terminal | A vault value; an approval it did not get from a person; looser rules; a receipt history that hides what it did |
| **A compromised project repo** | Supplies `.env`, `.morsec.toml`, `.git/config`, hooks, `.claude/settings*.json`, prompts and transcripts the agent reads | Anything the user's own rules do not already allow |
| **Other local users** | Connect to loopback TCP ports; see `ps` output; read world-readable files | Any use of the socket, the proxy or a value |
| **The network** (upstream providers, DNS, redirects, a MITM on the far side) | Answer requests, redirect, echo request content, poison DNS | A value sent to a host it is not bound to; morsec talking to a private address |

Root, a kernel compromise, and physical access are out of scope (same as the Keychain's model).

## Trust boundaries

| Boundary | Sides | What crosses | What checks it |
|---|---|---|---|
| **msd IPC socket** (`~/Library/Application Support/morsec/msd.sock`, framed JSON, `crates/ms-ipc`) | Clients: `ms`, `ms-shim`, `ms mcp`, `ms approve` (the agent or the user, same uid) → `msd` | Requests (status, stop/start, rules, put key with a raw value frame, run, MCP calls, approvals, scan); responses never carry a value | 0600 socket in a 0700 dir opened `O_NOFOLLOW` (`Server::bind_with`); peer uid + session from the kernel peer PID (`SessionPeerCheck`); frame limits (`read_frame`, 1 MiB); per-peer, lifetime and request caps; reserved slots for `Status`/`Stop`; policy (`ms_rules::decide`) and the approver in msd. The client checks only that the server has the same uid (`Client::connect`) |
| **Swap proxy** (`127.0.0.1:<port>`, `crates/ms-proxy`, run by msd) | Agent processes (HTTP proxy clients) → msd → upstream over TLS | Requests carrying `ms://` placeholders in; the value out, only to a bound host, only in the bound location; responses back unchanged | Session from loopback port → PID → process tree (`PortResolver::resolve`, `Sessions::resolve`); bound/allowlist check (`Proxy::connect`); SSRF guard (`ssrf::check`); SNI and Host must match the tunnel (`mitm`, `inspected`); `rewrite::plan`/`apply`; policy + approver; a receipt before anything is sent; rustls with system roots upstream (`tls::client_config`) |
| **Run mode** (`ms-shim`, `ms run`, `crates/ms-run`, adapters for psql/prisma, ssh, git) | Agent supplies argv, cwd, env, stdin → msd builds and runs the child → output back through a redactor | argv, cwd, env names with `ms://` refs, stdin; the value goes into the child (passfile, SSH agent, env named by the rule) | `input::check_argv`/`check_env`, trusted program resolution (`resolve.rs`), project roots (`cwd::check`), `decide_run` with the argv hash, adapters (`psql_args::parse`, `ssh_git::args`, `repo::config_violation`), approver for production keys, streaming redactor (`redact.rs`), process-group kill |
| **`ms mcp`** (stdio server, `crates/ms-mcp`, `crates/ms-cli/src/mcp.rs`; enforced in `crates/msd/src/daemon/mcp.rs`) | The agent's MCP client → `ms mcp` → msd `McpCall` | Tool name, rules version, cwd, JSON arguments in; inert command output out | Catalog rebuilt in msd from the MAC'd rules (`Catalog::from_rules`); stale version refused; JSON Schema in msd (`schema::validate`: string ≤ 4096, no NUL, no `ms://`, no extra properties); then the same run-mode path; results wrapped inert (`result.rs`) |
| **Connector settings files** | `ms connect` (the user) writes; the agent reads them at start and can also edit them | Proxy port, sandbox flags, CA bundle paths, `ms://` refs, MCP entries | `ms-connect` writes refs only and never a bypass (`check_ref_env`, `plan_settings`); `disconnect`/`--force` refused inside an agent; msd drift watcher (`drift::watch_loop`) alerts on change of the two watched files; `ms doctor` reports drift |

## Threat table

STRIDE: **S**poofing, **T**ampering, **R**epudiation, **I**nformation disclosure, **D**enial of
service, **E**levation of privilege (first letter is the main one).

Status: `mitigated` (control in place and a test proves it), `partial` (control in place but a
known gap or no test), `open` (no control yet), `accepted` (recorded as accepted risk). Test
paths are `file::test_name`. Tests marked "(added in this loop)" are the `hardening` loop's fuzz
targets.

## How to keep this current

- Each loop that adds or changes a trust boundary, an asset or a control updates this file in the
  same PR: new rows for new threats, status changes for closed ones, and the test that proves it.
- Every test named here must exist. Check before merging:
  `grep -rn "fn <name>" crates tests` for each name.
- A new boundary (mint mode, a new connector, Linux, an isolated runner user) means re-running
  this model for that boundary before its PR ships, not after.
- When a row moves to `accepted`, record the exception in `ARI42.md` ("Exceptions") with who
  accepted it and a review date.
- Keep the ARI-42 ids in step with `ARI42.md`; the scope line at the top names the commit the
  table describes.
